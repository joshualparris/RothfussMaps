ENGINE - src/engine/inventoryEngine.ts
═══════════════════════════════════════

Implement and export:

  getInventoryDisplayLines(state: PlayerState): string[]

    state: PlayerState,

  ): InventoryItem | null

    state: PlayerState,

    query: string
  ): { message: string; newState: PlayerState }

  getClothingDescription(quality: ClothingQuality): string

Rules:

─────────────────────────────────────
getInventoryDisplayLines(state)
─────────────────────────────────────

Return a stable list of human-readable inventory lines.

Rules:
- Use ITEM_REGISTRY display_name where possible
- Include quantity suffix only when quantity > 1
- Include notes only when helpful and compact
- If the lute is present, it should stand out naturally but not with
  decorative formatting
- Also include clothes as a separate line derived from clothing_quality,
  even if not in inventory:
    e.g. "Clothes: worn"
- If inventory is otherwise empty, still show clothes line

Example acceptable lines:
  "Kvothe's lute"
  "tallow candle x3"
  "lecture notes"
  "Clothes: worn"

─────────────────────────────────────
findInventoryItem(state, query)
─────────────────────────────────────

Rules:
- Case-insensitive matching
- Accept simple aliases:
    lute -> lute
    candle / tallow candle -> candle_tallow
    wick / wicking -> wicking
    drab / iron drab -> iron_drab
    clay -> clay_lump
    pitch / pine pitch -> pine_pitch
    wax -> wax_stub
    notes / lecture notes -> lecture_notes
    clothes / clothing -> special-case handled separately
- Return the matching InventoryItem if present
- Return null if not present
- For clothes, return null here; clothes are handled by examine/use logic directly

─────────────────────────────────────
getClothingDescription(quality)
─────────────────────────────────────

Return deterministic text:

  poor         -> "Your clothes are poor and plainly mark your means."
  worn         -> "Your clothes are worn but still serviceable enough for daily use."
  serviceable  -> "Your clothes are plain, decent, and fit for ordinary student life."
  good         -> "Your clothes are in good order and sit well enough on you."

Return those exact strings.

─────────────────────────────────────
examineItem(state, query)
─────────────────────────────────────

Rules:
- If query refers to clothes/clothing:
    return getClothingDescription(state.clothing_quality)
- Else look up the inventory item and registry definition
- If item is not present:
    return "You are not carrying that."
- If registry definition is missing:
    return a brief generic line:
      "There is nothing especially notable about it at a glance."
- Otherwise return the item's default_examine_text
- If the item has inventory notes, it is acceptable to append them
  after a blank line if that improves clarity, but keep it brief

Do not create new state changes here.

─────────────────────────────────────
useItem(state, query)
─────────────────────────────────────

Rules:
- If query refers to clothes/clothing:
    return a brief line about straightening or checking your clothes
    state unchanged

- If item is not present:
    return "You are not carrying that."
    state unchanged

- If the item is lute:
    return a careful, in-world line about handling or readying the lute
    state unchanged
    Do not trigger performance automatically in this prompt

- If the item category is sympathy_material:
    return a brief line about preparing or weighing the material in hand
    state unchanged
    Do not trigger sympathy automatically in this prompt

- If the item is lecture_notes:
    return a brief line about skimming or steadying your thoughts on the page
    state unchanged
    Do not add a study mechanic

- For any other usable registry item:
    return default_use_text
    state unchanged

- For non-usable items:
    return "That is not something you can make use of just now."
    state unchanged

This prompt adds flavourful use/examine behaviour only.
It does not add item-consumption mechanics.
