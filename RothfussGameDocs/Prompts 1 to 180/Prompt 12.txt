GOAL OF THIS PROMPT
═══════════════════════════════════════
By the end of Prompt 12, the player should be able to:
  - type `listen`, `listen for rumours`, or `ask around`
  - hear one rumour at a time from the current location
  - receive only rumours appropriate to the current location
  - unlock some rumours only after spending enough time in a place
  - unlock some rumours only if their reputation is high enough
  - hear conflicting rumours on mystery-adjacent topics without the
    system resolving which one is true
  - avoid hearing the exact same rumour repeatedly once already heard
The system should make the world feel socially alive and uncertain.

ENGINE — src/engine/rumourEngine.ts
═══════════════════════════════════════
Implement and export:
  getRelevantRumours(
    state: PlayerState,
    locationId: string
  ): RumourEntry[]
  getNextRumour(
    state: PlayerState,
    locationId: string
  ): RumourEntry | null
  hearRumour(
    state: PlayerState,
    locationId: string
  ): { message: string; newState: PlayerState }
  incrementLocationDwell(
    previousState: PlayerState,
    newState: PlayerState,
    command: string
  ): PlayerState
Rules:
─────────────────────────────────────
getRelevantRumours(state, locationId)
─────────────────────────────────────
Return rumours from RUMOUR_POOL that:
- match location_id
- have not already been heard
- pass minimum_dwell_turns
- pass minimum_social on the correct reputation axis
Reputation axis:
- if applies_to === 'university_social'
    use state.reputation.university_social
- if applies_to === 'eolian_standing'
    use state.reputation.eolian_standing
- if applies_to === 'academic_standing'
    use state.reputation.academic_standing
Keep original array order.
Do not sort dynamically.
Deterministic only.
─────────────────────────────────────
getNextRumour(state, locationId)
─────────────────────────────────────
Return the first eligible unheard rumour from getRelevantRumours().
If none exist, return null.
Do not randomise.
One-at-a-time delivery only.
─────────────────────────────────────
hearRumour(state, locationId)
─────────────────────────────────────
Behaviour:
- if getNextRumour() returns a rumour:
    add its id to heard_rumour_ids
    return:
      message: the rumour text
      newState: updated state
- if no eligible rumour exists:
    return one of these deterministic fallback lines based on
    state.day_number % 3:
"    0 -> ""You linger a while, but nothing new reaches your ear."""
"    1 -> ""There is talk enough, but none of it turns into anything worth keeping."""
"    2 -> ""You listen, but what drifts past is old noise and nothing more."""
Do not mutate reputation in this prompt.
─────────────────────────────────────
incrementLocationDwell(previousState, newState, command)
─────────────────────────────────────
This is a lightweight helper for tracking time spent in a place.
Rules:
- if newState.location_id !== previousState.location_id:
    reset current_location_turns to 0
- else if command is one of:
    look
    look around
    wait
    talk to ...
    ask ...
    listen
    listen for rumours
    ask around
  then increment current_location_turns by 1
- else leave current_location_turns unchanged
Return a new PlayerState.
Deterministic only.
This helper should be called from actions.ts after command resolution,
without changing the meaning of the command itself.
