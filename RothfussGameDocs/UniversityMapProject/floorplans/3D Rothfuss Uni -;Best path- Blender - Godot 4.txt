Best path: Blender + Godot 4.
Why that stack:
* Blender is the cleanest way to turn your floor plans into accurate 3D architecture.
* Godot 4 is free, good for first-person walking, easy to structure building-by-building, and simpler than Unreal for this sort of explorable reconstruction.
* If you want it to stay inside your current website later, you can export the same models to a Three.js / React Three Fiber viewer after the Godot version works.
The big rule is this:
Do not build the 3D world from the rendered PNG floor plans alone.
 Build it from a canonical floor data package for each building and floor, then use the floor plan images only as visual tracing references.
The right pipeline
1. Freeze one authoritative source per floor
For each building and floor, create one structured file that contains:
* outer footprint
* wall lines
* wall thicknesses
* door positions
* stair positions
* window positions
* room labels
* certainty tags: canon / implied / reconstructed
* links to source prompt / book evidence
Use something like:
* json
* yaml
* or even svg + metadata
Example: archives/ground_floor.json hollows/basement.json mains/ground_floor.json
This matters because if you change a prompt later, your 3D model should still be anchored to one stable plan.
2. Trace each floor plan in Blender
Import each approved floor plan image into Blender as a reference image on the XY plane.
Set:
* 1 Blender unit = 1 metre
* north always aligned the same way
* one collection per floor
* one collection per building
Then trace:
* exterior walls first
* major corridors
* stairs
* fixed room shells
* then secondary partitions
Do blockout first, not detailed modelling.
3. Standardise vertical assumptions
Your floor plans are mostly horizontal. A walkable 3D game needs vertical conventions.
Pick one project-wide vertical standard and stick to it:
* public institutional floor height: around 4.0–4.8 m
* ordinary upper floors: around 3.2–4.0 m
* basement / utility floors: 3.0–3.8 m
* stair riser: around 170 mm
* stair tread: around 280 mm
* door height: around 2.1–2.4 m
* major hall doors can be taller
These are reconstructed conventions, not canon, so keep them in a shared config file.
4. Model each building as a stack of aligned floors
For each building:
* Ground floor at Z = 0
* Upper floors stacked exactly above
* Basement below
* Stair openings aligned vertically
* Exterior walls aligned unless canon says the upper or lower floor differs
You want:
* Building shell
* Floor slabs
* Walls
* Doors
* Stairs
* Props
* Lighting markers as separate layers or collections
5. Keep “game mesh” and “hero mesh” separate
Make two versions:
* Game mesh = simple, low-poly, clean collision
* Hero mesh = nicer version for final visuals
At first, only build the game mesh.
That means:
* plain walls
* simple floors
* simple door frames
* simple stairs
* no decorative clutter
* no tiny books, pipes, or furniture unless needed for navigation
6. Export to Godot as GLB
Use .glb exports from Blender.
One file per building is usually best:
* archives.glb
* hollows.glb
* mains.glb
* medica.glb
Or if a building is huge:
* mains_ground.glb
* mains_upper.glb

Transforming these "canon-constrained" reconstructions into a walkable 3D environment is a massive undertaking, but honestly, it’s the ultimate dream for any *Kingkiller* fan. Since you have the floor plans, you have the "blueprint" layer finished. Now you need to move into the **Digital Stonework** phase.
Here is the roadmap to turning these 2D plans into a 1:1 virtual University.
## 1. Pick Your Engine
For a project focusing on atmospheric lighting and interior "vibes," you have two main contenders:
 * **Unreal Engine 5 (UE5):** Best for **Atmosphere**. Its "Lumen" lighting system is perfect for those unwavering sympathy lamps and the silvery moonlight on the Masters' Hall. It handles massive architectural detail very well.
 * **Unity:** Best for **Accessibility**. If you’re new to coding, Unity has a massive library of "First Person Controller" assets that will get you walking in minutes.
## 2. The "Blueprint to Bricks" Workflow
You can't just drop a 2D image into a game and expect it to have collisions. You need to **extrude** the geometry.
### Step A: Reference Planes
Import the floor plan images as a "Plane" in a 3D modeling tool like **Blender** or directly into the engine using a tool like **ProBuilder** (Unity) or **Modeling Mode** (Unreal). Scale the plane so the 10m scale bar on the image matches 10 units in the engine.
### Step B: Blocking Out (Greyboxing)
Trace the walls. Don't worry about textures yet. Just create simple boxes where the walls are.
 * **Archives:** Focus on the thick, windowless outer shell first.
 * **Mains:** This will be your hardest task because of the "lichen-like" growth. You'll need to vary the heights of different "absorbed" building sections.
## 3. Mastering Verticality
Accuracy depends on how the floors stack.
 * **Vertical Alignment:** Create a "Master Stairwell" object. In the Archives, align the **Southeast Stairwell** across all 6 floors. If the stairs don't line up perfectly due to AI generation quirks, you’ll have to "nudge" the floor plans until the stairs create a continuous path.
 * **The Underthing:** This should be its own "level" or a massive basement. Use the "Drainage Grate" in the **Hidden Apple-Tree Courtyard** of Mains as your vertical anchor.
## 4. Canon-Accurate Lighting
Lighting is what makes the University feel real. You’ll want to use **Baked Lighting** for the Archives and **Dynamic Lighting** for areas with "magic."
 * **Sympathy Lamps:** Place small, point-light sources with a slightly reddish/warm hue in the Archives and Tomes.
 * **The "Circle of Light":** In the Admissions Theatre, use a **Spotlight** with a sharp falloff to create that interrogation feel.
 * **The Stacks:** Keep the ambient light at near-zero. Force the player to use a "Hand Lamp" (a point light attached to the player's camera) to see the shelving labels.
## 5. Interaction and "Feel"
Walking is easy; interacting is where the lore comes alive.
| Feature | Implementation |
|---|---|
| **Heavy Doors** | Use "Physics Constraints." The stone doors of the Archives should feel heavy and slow to open. |
| **The "Sticky" Door** | For Elodin's Naming Hall, write a simple script that requires the player to "Interact" 3 times before the door successfully opens. |
| **Lockpicking** | In Hollows, you can implement a simple UI mini-game to simulate Kvothe picking the two locks to get into the observation area. |
## 6. Dealing with "The Labyrinth" (Mains)
Since Mains is an "acre and a half" of nonsense, it will be your biggest performance hurdle.
 * **Level Streaming:** Only load the wing the player is currently in.
 * **NavMesh:** You'll need to generate a "Navigation Mesh" so the engine knows where the floor is. Because Mains has "stairs to nowhere," you might find your character getting stuck in "bricked-off" rooms. You’ll have to manually "clip" these areas so the player can't phase through the walls into the void.
### Pro-Tip: The "Blender" Shortcut
If you want to be *truly* accurate, I recommend using **Blender** to build the 3D shells first. Trace the floor plans, "E" (Extrude) the walls up to a standard 3-4 meter height, and then export that as an .FBX file into your game engine.

To do this with "least effort," you have to stop thinking like an architect and start thinking like a **systems integrator**. You want to use a pipeline where one AI interprets the plan and another AI builds the geometry.
Here is the "Lazy Path" to a walkable University, ranked by speed and automation.

The fastest way to get walls is to use a dedicated **Floor Plan to 3D** service. These are usually designed for real estate, but they work for "Tomes" or "The Medica" if the lines are clean.
 * **Tools:** **CubiCasa**, **Planner 5D**, or **Canvas (by Occipital)**.
 * **Process:** 1.  Upload the generated floor plan image.
   2.  The AI identifies "walls," "doors," and "openings."
   3.  Export as an .OBJ or .FBX.
 * **Downside:** These tools struggle with the "Underthing" or "Mains" because they expect 90-degree residential walls. They might try to turn a "Runic Grate" into a window.
## 2. The "Blender Scripting" Shortcut (The Pro-Automation Path)
Since you already have clean black-and-white plans, you can use **ChatGPT or me (Gemini)** to write a **Python script for Blender** that automates the extrusion.
 * **The Workflow:**
   1. **Image Processing:** Use a simple AI tool to "Vectorize" your floor plan (convert it to an .SVG).
   2. **AI Scripting:** Ask an AI: *"Write a Blender Python script that imports an SVG, selects all paths, and extrudes them by 4 meters on the Z-axis."*
   3. **Result:** You get a full 3D shell of the floor in seconds without manually dragging a single wall.
## 3. Generative AI for Furniture & Props (Populating the Rooms)
You don't want to spend hours modeling "300 Archive Shelves" or "Hemme’s Chair." Use **Text-to-3D** or **Image-to-3D** generative models.
 * **Tools:** **Meshy.ai**, **Rodin (Deemos)**, or **Luma AI Genie**.
 * **Process:** 1.  Take a screenshot of a specific room label (e.g., "Bursar’s Counter").
   2.  Feed it into the AI with the prompt: *"A 17th-century heavy oak bursar's counting desk, dark wood, realistic, game-ready."*
   3.  Download the asset and drop it into your engine.
## 4. Total Automation: AI Game Engines
There are emerging platforms where you can "describe" the floor plan and they build the environment for you.
 * **Tool:** **Promethean AI**. This is an AI that works *inside* Unreal Engine. You can tell it: *"This is a library room. Populate it with bookshelves and long tables consistent with the layout."* It will automatically search your asset library and place items in the "Tomes" room based on the floor plan's logic.
 * **Tool:** **Hume AI or Convai**. For the "Characters," you can give an AI NPC (like Puppet or Master Kilvin) the *Kingkiller* lore, and they will talk to you naturally as you walk through your built environment.

Here is the roadmap to turning these 2D plans into a 1:1 virtual University.
## 1. Pick Your Engine
For a project focusing on atmospheric lighting and interior "vibes," you have two main contenders:
 * **Unreal Engine 5 (UE5):** Best for **Atmosphere**. Its "Lumen" lighting system is perfect for those unwavering sympathy lamps and the silvery moonlight on the Masters' Hall. It handles massive architectural detail very well.
 * **Unity:** Best for **Accessibility**. If you’re new to coding, Unity has a massive library of "First Person Controller" assets that will get you walking in minutes.
## 2. The "Blueprint to Bricks" Workflow
You can't just drop a 2D image into a game and expect it to have collisions. You need to **extrude** the geometry.
### Step A: Reference Planes
Import the floor plan images as a "Plane" in a 3D modeling tool like **Blender** or directly into the engine using a tool like **ProBuilder** (Unity) or **Modeling Mode** (Unreal). Scale the plane so the 10m scale bar on the image matches 10 units in the engine.
### Step B: Blocking Out (Greyboxing)
Trace the walls. Don't worry about textures yet. Just create simple boxes where the walls are.
 * **Archives:** Focus on the thick, windowless outer shell first.
 * **Mains:** This will be your hardest task because of the "lichen-like" growth. You'll need to vary the heights of different "absorbed" building sections.
## 3. Mastering Verticality
Accuracy depends on how the floors stack.
 * **Vertical Alignment:** Create a "Master Stairwell" object. In the Archives, align the **Southeast Stairwell** across all 6 floors. If the stairs don't line up perfectly due to AI generation quirks, you’ll have to "nudge" the floor plans until the stairs create a continuous path.
 * **The Underthing:** This should be its own "level" or a massive basement. Use the "Drainage Grate" in the **Hidden Apple-Tree Courtyard** of Mains as your vertical anchor.
## 4. Canon-Accurate Lighting
Lighting is what makes the University feel real. You’ll want to use **Baked Lighting** for the Archives and **Dynamic Lighting** for areas with "magic."
 * **Sympathy Lamps:** Place small, point-light sources with a slightly reddish/warm hue in the Archives and Tomes.
 * **The "Circle of Light":** In the Admissions Theatre, use a **Spotlight** with a sharp falloff to create that interrogation feel.
 * **The Stacks:** Keep the ambient light at near-zero. Force the player to use a "Hand Lamp" (a point light attached to the player's camera) to see the shelving labels.
## 5. Interaction and "Feel"
Walking is easy; interacting is where the lore comes alive.
| Feature | Implementation |
|---|---|
| **Heavy Doors** | Use "Physics Constraints." The stone doors of the Archives should feel heavy and slow to open. |
| **The "Sticky" Door** | For Elodin's Naming Hall, write a simple script that requires the player to "Interact" 3 times before the door successfully opens. |

## 6. Dealing with "The Labyrinth" (Mains)
Since Mains is an "acre and a half" of nonsense, it will be your biggest performance hurdle.
 * **Level Streaming:** Only load the wing the player is currently in.
 * **NavMesh:** You'll need to generate a "Navigation Mesh" so the engine knows where the floor is. Because Mains has "stairs to nowhere," you might find your character getting stuck in "bricked-off" rooms.
```python
import json
import os


def validate_university_data(data_dir):
    report = {"errors": [], "warnings": [], "stats": {"rooms": 0, "certainty": {}}}
    buildings = {}


    # Load all floor JSONs
    for file in os.listdir(data_dir):
        if file.endswith(".json"):
            with open(os.path.join(data_dir, file), 'r') as f:
                data = json.load(f)
                b_id = data['building_id']
                if b_id not in buildings: buildings[b_id] = {}
                buildings[b_id][data['floor_id']] = data


    for b_id, floors in buildings.items():
        for f_id, f_data in floors.items():
            # 1. Room Metadata & Stats
            for room in f_data['geometries']['rooms']:
                report['stats']['rooms'] += 1
                c = room['certainty']
                report['stats']['certainty'][c] = report['stats']['certainty'].get(c, 0) + 1


            # 2. Stair Alignment Check (The Stair-Link)
            for stair in f_data['geometries'].get('vertical_circulation', []):
                target = stair['target_floor']
                if target in floors:
                    # Look for matching stair in target floor
                    target_floor = floors[target]
                    match_found = False

                        # Check X/Z alignment within 0.1m tolerance
```

### 1. The Godot Doorway Trigger System
This system handles scene transitions and logic-gated entries (like the Master's Hall side door). Instead of hard-coding every door, we use a single script that reads the portals data from the floor JSON files.
**Script: DoorwayTrigger.gd**
```gdscript
extends Area3D


@export var target_building: String = ""
@export var target_entrance_id: String = ""
@export var requires_key: String = "" # e.g., "brass_key"


func _ready():
    # Connect the body_entered signal to handle player detection
    body_entered.connect(_on_body_entered)


func _on_body_entered(body):
    if body.is_in_group("player"):
        if requires_key != "" and not body.has_item(requires_key):
            # Trigger UI feedback for a locked door
            SignalBus.emit_signal("display_message", "The door is locked.")
            return
            
        # Trigger the building transition
        transition_to_building()


func transition_to_building():
    # Communicate with the Global Building Loader to swap scenes or teleport
    var transition_data = {
        "building": target_building,
        "entrance": target_entrance_id
    }
    SignalBus.emit_signal("request_building_transition", transition_data)
```
